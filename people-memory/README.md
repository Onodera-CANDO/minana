# People Memory（AI人脈アシスタント PWA MVP）

スマートフォンのブラウザで動き、ホーム画面に追加できる**ローカルファースト**の人脈メモ PWA です。
Sansan 等の名刺 CSV 取込と手動登録で人物を管理し、**本人の同意を得て顔を登録した人だけ**をカメラで照合して、名前・会社・役職・前回の面会内容をすぐ確認できます。

- 名刺データ・顔特徴量・面会履歴は**端末内の IndexedDB に暗号化して保存**。サーバー・外部AI・クラウド顔認識には送信しません。
- 照合結果は「候補」止まり。**自動確定・自動の面会加算はしません**。
- バックエンド不要。任意の静的 HTTPS ホスティングで動きます。

> 仮称です。正式なサービス名は未定。仕様書: `AI_People_Memory_PWA_MVP_Spec_v1.0`（2026-10-12）

## 起動方法

必要環境: Node.js 20 以上（開発は 22 で確認）

```bash
cd people-memory
npm ci                 # 依存関係（バージョン固定）
npm run dev            # 開発サーバー http://localhost:5173 （顔モデルを public/models にコピーしてから起動）
```

- `localhost` はセキュアコンテキスト扱いなので、PC ではそのままカメラも使えます。
- **スマホ実機でカメラを使うには HTTPS が必要**です（`http://192.168.x.x` ではカメラ不可）。下記「実機での確認」を参照。
- 開発サーバーでは Service Worker は無効です（PWA/オフラインは `build` + `preview` で確認）。

### その他のコマンド

| コマンド | 内容 |
|---|---|
| `npm run build` | 型チェック＋本番ビルド（`dist/`）。CSP 付与・SW 生成 |
| `npm run preview` | ビルド結果をローカル配信（http://localhost:4173） |
| `npm test` | ユニット／統合テスト（Vitest, 46件） |
| `npm run typecheck` | 型チェックのみ |
| `npm run e2e` | `build` 後に実行。headless Chromium（390×844）で主要導線のスモークテスト。スクリーンショットは `test-results/` |
| `npm run gen:csv` | `sample-data/` のダミー CSV を再生成（CP932 版は `iconv` が必要） |
| `npm run copy-models` | 顔モデルを `node_modules/@vladmandic/human/models` から `public/models` にコピー（dev/build 前に自動実行） |

E2E は Chromium のパスを自動検出します（`/opt/pw-browsers/...`）。別の場所なら `CHROMIUM_PATH=/path/to/chrome npm run e2e`。

## デプロイ方法（静的 HTTPS ホスティング）

`npm run build` で出力される `dist/` をそのまま配信するだけです。

- `base: './'`＋HashRouter なので、**サブディレクトリ配信・リライト設定なし**で動きます（GitHub Pages / Cloudflare Pages / Netlify / Firebase Hosting / S3+CloudFront など）。
- **HTTPS 必須**（カメラ・Service Worker・Web Crypto のため）。
- 推奨: CSP はビルド時に `<meta>` で付与済み。ホスティング側で HTTP ヘッダーとして `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Permissions-Policy: camera=(self), microphone=()` を付けるとより堅牢です（`frame-ancestors` はメタタグでは効かないので、クリックジャッキング対策は HTTP ヘッダー `frame-ancestors 'none'` で）。
- 顔モデル（約 9MB）は `dist/models/` に含まれ、Service Worker が初回にキャッシュします。外部 CDN には依存しません。
- アクセス解析・エラートラッカー等は**入れないでください**（仕様 8.2 / 10.2）。

### 実機での確認（スマホから HTTPS で開く）

いずれかで HTTPS の URL を用意します。

1. 上記の静的ホスティングにデプロイする（推奨・本番相当）
2. 同一 LAN で開発する場合は、`vite preview` を HTTPS 化するか、HTTPS トンネル（cloudflared 等）を使う
   - トンネル利用時はアプリシェルが第三者経由で配信されます。個人データは端末外に出ませんが、検証用途に限定してください。

## 使い方（主要導線）

1. **初回セットアップ**: データ保管の説明に同意 → パスフレーズ設定（10文字以上）。パスフレーズはどこにも保存しません。**忘れると復号できません**。
2. **人物登録**: 「＋人物を追加」で手入力（重複候補を保存前に表示）／「CSVを取り込む」。どちらも同じ人物IDと詳細画面です。
3. **CSV取込**: 規程確認 → 出典（Sansan / その他）→ ファイル選択 → 文字コード確認（UTF-8 優先、不正なら Shift_JIS 自動。手動切替可）→ 列の割当（自動推定）→ 新規／更新候補／重複要確認／無効のプレビュー → 取込 → 結果（保留の解決、問題行 CSV のダウンロード）。
4. **顔登録**（任意）: 人物詳細 → 「顔を登録する」→ 本人への説明と同意をチェック → カメラ起動 → 品質ガイドに従い 3 枚撮影 → 特徴量を保存（画像は保存しない）。
5. **照合**: カメラタブ → 「カメラを起動」→ 候補カード → 「この人で合っている」で詳細へ → 「今日会った」で面会記録。違うときは「違う」または「手動検索に切替」。
6. **バックアップ**: 設定 → バックアップ／復元。独立したパスフレーズで暗号化したファイルを書き出し、PC 等にも保管してください。

### 顔照合の閾値について（重要）

閾値はモデル・端末・登録人数・撮影環境で変わるため、**初期状態では「未校正」として候補の自動表示を無効**にしています（照合は動くが候補は出さず、手動検索を案内）。

1. 同意済みの協力者数人の顔を登録
2. カメラ画面で「校正モード」をオン → 本人／他人を映したときの類似度スコア（**本人確率ではない**）と 1位/2位の差を記録
3. 設定 → 顔照合で「最低類似度」「1位と2位の差」「安定フレーム数」を調整し、「閾値を校正済み」をオン

暫定初期値: 最低類似度 0.70・差 0.08・安定 3 フレーム（いずれも未検証の保守的な値）。

## 構成

```
people-memory/
  src/
    app/            App・ルーティング・Zustand ストア（復号データはロック解除中のみメモリ保持）・自動ロック
    components/     共通 UI・PersonCard・CameraPreview・PersonPicker
    pages/          SCR-01〜12 の各画面
    features/
      people/       正規化・検索・重複候補・デモデータ
      csv-import/   文字コード判定・パース・列マッピング・分類（plan）・適用（apply）・安全な CSV 出力
      face-recognition/  FaceRecognitionAdapter / HumanFaceAdapter / recognitionPolicy / quality / camera
      meetings/ relations/ backup/
    storage/        Dexie スキーマ・暗号化リポジトリ・設定・マイグレーション
    security/       Web Crypto（PBKDF2→KEK、DEK ラップ、AES-GCM）・ロックセッション
    pwa/            SW 登録・更新通知・インストール案内・永続化要求
    tests/          Vitest
  public/           manifest・アイコン・models/（ビルド時にコピー、git 管理外）
  sample-data/      ダミー CSV
  scripts/          モデルコピー・ダミー CSV 生成・E2E スモーク
```

### データ保護の設計

- **鍵**: パスフレーズ →（PBKDF2-SHA256, 310,000 回, 16B salt）→ KEK。ランダムな 256bit DEK を KEK でラップして保存。パスフレーズ・KEK は保存しない。パスフレーズ変更は DEK の再ラップのみ。
- **レコード**: 人物・顔特徴量・面会・関係・取込履歴をそれぞれ AES-GCM（12B IV, AAD=`種別:ID`）で暗号化し IndexedDB の `records` に保存。平文の索引は種別と UUID のみ（漏えい時に推測できるのは件数程度）。
- **平文で保存するもの**: 個人情報を含まない設定値（自動ロック時間・閾値等）と非個人の検証統計のみ。LocalStorage は使っていません。
- **メモリ**: ロック解除中のみ復号データをメモリに保持し、ロック（手動・自動・再読込）で破棄。JS メモリ上の漏えいリスクは残ります（仕様 10.2）。
- **バックアップ**: アプリのパスフレーズとは独立したパスフレーズで同方式の暗号化。形式・スキーマはバージョン付き。
- **通信**: CSP `connect-src 'self'`。E2E で外部オリジンへのリクエストが 0 件であることを確認。
- **XSS**: CSV 由来の文字列は React のテキストとして描画（`dangerouslySetInnerHTML` 不使用）。問題行 CSV 出力時は `= + - @ タブ CR` 始まりのセルに `'` を付与。

## 既知の制限・注意事項

- **ブラウザはデータを削除することがあります**（容量逼迫、サイトデータ削除、iOS の一定期間未使用時の削除等）。定期的なバックアップが前提です。ホームにバックアップ案内を出します（初回データ登録後・最終バックアップから 14 日）。
- **パスフレーズ・バックアップのパスフレーズを忘れると復旧手段はありません**（バックドアなし）。
- 顔照合の精度・速度は未検証です。性能や精度は保証しません。
- iOS Safari は機能差があり、実機検証まで完全対応を保証しません。
- 自動ロックは「操作なし N 分」または「非表示のまま N 分経過して復帰」で発動。ページ再読込でも必ずロックされます。
- 依存関係: 本番依存の `npm audit` は react-router の moderate 1 件（`<Link>`/`navigate` に外部入力のパスを渡す場合のオープンリダイレクト。本アプリは利用者入力をナビゲーション先にしないため影響は限定的）。開発依存（vitest 2 系 / tailwind 3 系の周辺）に既知の脆弱性があり、配信物には含まれません。メジャー更新は別途検証のうえ実施してください。
- CSV を取り込む前に、Sansan の利用契約・出力権限・社内規程でデータ持ち出しと私的利用が認められているか確認してください。**出力できることと私的利用が許されることは別**です。
- 一般向け販売・組織利用へ移行する前に、法務（個人情報保護法・個人情報保護委員会ガイドライン）・セキュリティ・第三者サービス規約・モデルの利用条件・特許の確認が必要です。本アプリ・本 README は法的許諾を保証しません。
