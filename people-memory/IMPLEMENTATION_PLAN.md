# IMPLEMENTATION_PLAN — People Memory PWA MVP

仕様書: `AI_People_Memory_PWA_MVP_Spec_v1.0`（2026-10-12）
優先順位: **データ保護 > 誤認識抑制 > 人物管理の確実性 > 操作性 > 演出**

凡例: `[x]` 実装済み・自動テスト/E2E で確認 / `[~]` 実装済み・実機未確認 / `[ ]` 未着手

> 「実機で確認していない事項は動作確認済みと書かない」方針のため、Android/iPhone 実機での確認はすべて `[~]` または `[ ]` としている。

## 0. Must / Won't の境界と不確定点の整理

- Must（2.2 の 1〜10）はすべて MVP 範囲として実装。
- Won't（2.3）は実装しない：スマートグラス／Sansan API／常時スキャン・録音／属性推定／クラウド同期 等。
- 不確定点（17章）と、それに対する保守的な扱い：

| 不確定点 | MVPでの扱い |
|---|---|
| Sansan 実CSVの列名 | 固定列にせず、同義語辞書による自動推定＋手動マッピング。想定列名でダミーCSVを作成 |
| 対象スマホ機種・Safari 対応範囲 | Android Chrome 優先。iOS は案内文を用意し、実機検証で制約を記録する |
| 顔モデルの精度・閾値・速度 | 閾値は暫定値・**未校正の間は候補の自動表示を無効**。校正モードでスコア分布を確認して設定 |
| パスフレーズ UX・永続性 | PBKDF2 + AES-GCM、DEK ラップ方式（変更容易）。`storage.persist()` 要求＋バックアップ案内 |
| モデルの配布条件 | `THIRD_PARTY_NOTICES.md` に確認済み/未確認を分けて記録 |

## Sprint 0 — 環境・基盤

- [x] React 18 + TypeScript + Vite 5 プロジェクト（`people-memory/`）
- [x] PWA: `manifest.webmanifest`・アイコン（192/512/maskable/apple-touch）・Service Worker（vite-plugin-pwa / generateSW）
- [x] アプリシェルと顔モデルを precache。CSV・個人データはキャッシュに入れない
- [x] 本番ビルドに CSP（`default-src 'self'` 等）を付与、`referrer: no-referrer`
- [x] モバイル UI 共通部品・下部タブ（ホーム / カメラ / 人物 / 履歴 / 設定）・HashRouter
- [x] IndexedDB（Dexie）・暗号化リポジトリ（AES-GCM, AAD=レコードキー）
- [x] 初回セットアップ（保管説明・パスフレーズ・権限案内）・ロック画面・自動ロック
- [x] Vitest テスト基盤・Playwright スモーク E2E
- [x] オフラインでのホーム表示（E2E: Service Worker 経由でオフライン再読込→解除→ホーム）
- [~] Android Chrome 実機でホーム画面追加 → オフライン起動

**完了条件:** Android Chrome でホーム画面追加でき、初回セットアップ後にオフラインでホームが表示できる → headless Chromium では確認済み。**実機は未確認**。

## Sprint 1 — 人物データ管理

- [x] 人物の手動新規登録・一覧・詳細・編集・削除（確認ダイアログ、関連データの扱いを明示）
- [x] 検索（キーワード／ふりがな／会社／タグ／顔登録状況）・空状態・フォーム検証
- [x] 手動登録時の重複候補（メール／氏名＋会社／氏名のみ）を保存前に提示
- [x] 面会履歴の作成・編集・削除、同日同一イベントの重複警告、面会回数は面会レコード数
- [x] 共通の知人・紹介者（登録済み人物 or 未登録の名前メモ）
- [x] ダミー人物データ（設定 → デモ用ダミーデータを追加）

**完了条件:** 顔認識なしで「人を覚えるメモアプリ」として利用できる → 達成。

## Sprint 2 — CSV取込・バックアップ

- [x] ファイル選択・サイズ上限（10MB）・UTF-8(BOM有無)優先／不正なら Shift_JIS(CP932) 自動切替・手動切替
- [x] Papa Parse による RFC4180 パース（引用符・改行・カンマ）
- [x] ヘッダー自動推定＋手動マッピング・氏名1列 or 姓/名・未割当列の確認と任意保存
- [x] プレビュー分類（新規／更新候補／重複要確認／無効）・CSV内重複（同一人物IDの複数名刺）
- [x] 重複判定ルール 4.4（外部ID は sourceSystem 単位、メール・氏名＋会社は要確認、名前だけでは重複扱いしない）
- [x] 更新差分プレビュー・手動編集項目との衝突表示（既定は保持）・空欄で既存値を消さない
- [x] 保留行を取込結果画面から後で解決（統合／別人登録／スキップ）
- [x] 取込レポート・問題行 CSV 出力（式インジェクション対策）
- [x] 再取込で顔特徴量・面会・関係・手動メモ・タグ・同意記録を保持（ユニット＋ストア統合テスト）
- [x] 暗号化バックアップ（独立パスフレーズ・PBKDF2・AES-GCM）／復元（検証・件数プレビュー・上書き確認）
- [x] 別ストレージへの復元（ユニット: 新DB、E2E: 別ブラウザコンテキスト）

**完了条件:** 再取込しても既存の手動メモ・面会記録が消えず、バックアップを別のブラウザストレージに復元できる → 達成（自動テスト）。

## Sprint 3 — 顔登録・照合

- [x] `FaceRecognitionAdapter` 抽象と `HumanFaceAdapter`（動的 import・自サイトのモデル・WebGL→CPU フォールバック）
- [x] 同意確認（説明済み／本人同意の2チェック）→ `consentAt / consentMethod / consentVersion` 保存
- [x] 品質チェック（1人・検出スコア・大きさ・正面度・明るさ・ブレ）→ 複数サンプル（既定3）
- [x] サンプル間の一貫性チェック・他の登録者との類似警告
- [x] 顔情報だけ削除・再登録（置き換え）
- [x] 照合ポリシー：絶対閾値・1位/2位差・複数フレーム安定性・未校正なら候補非表示
- [x] 不明／判別不可／顔なし／複数顔／低品質の表示、候補は「候補」と明示、利用者確認で詳細へ
- [x] 照合だけでは面会を追加しない（「今日会った」は別タップ）
- [x] カメラ停止（画面遷移・非表示・pagehide）→ E2E でトラック `ended` を確認
- [x] 校正モード（スコア表示）・非個人の検証ログ（端末内のみ）
- [x] 疑似カメラでモデル読込〜「顔が見つかりません」まで（headless Chromium）
- [ ] 同意済みの協力者数人での照合 PoC（**実機・実顔が必要。未実施**）
- [ ] モバイル実機での処理時間・発熱・メモリの実測

**完了条件:** 同意済みの数人で顔の照合が動作し、未知人物を無理に確定しない → **未達（実機検証待ち）**。精度未達の間は既定で候補提示を無効にしている。
